每个 ERP/MES 项目经理都经历过这种对话：客户说"这个改动很小的吧"，实施说"这要改底层逻辑"，最后双方在微信群里打太极。这个死结的解法，我踩了几年坑之后总结成一句话：**把变更变成一本账。**

## 为什么变更会失控

不是客户爱改，而是初期谁也说不清全部需求——尤其是制造业，很多流程只有跑起来才知道哪里不对。所以变更不可怕，**没有机制承接变更**才可怕。

## 我们的变更账本

一个共享表格，五列，半小时就能学会：

| 列 | 说明 |
|---|---|
| 编号/日期 | 谁、什么时候提的 |
| 变更内容 | 具体改什么，附原型或截图 |
| 影响评估 | 工时 + 影响范围，实施方填 |
| 决定 | 接受 / 缓冲期 / 拒绝 + 理由 |
| 状态 | 待评估 → 排期 → 已验收 |

## 三条规则，比工具重要

1. **所有变更走账本，不留口头承诺。** 哪怕客户是老板，也要说"好，我记进变更表，周四给你评估结果"。
2. **每周固定评审一次。** 集中决策，避免碎片化扯皮；当场定不了的就标缓冲期。
3. **月度对账。** 项目例会先过变更账：新增多少、完成多少、积压多少。积压持续增长就是预警信号。

## 效果

用这套东西之后最明显的变化：客户提变更前会自己先想清楚——因为知道提了就会被认真评估和计价。**可记录、可计价、可验收**，变更就从对抗变成了协作。

工具不限，一个共享文档就够。关键是双方都认这本账。
